## Allowed interface (exact — implement to this, do not redesign)

```js
// src/screens/dm-screen.js
import { deriveDisplayView } from '../board/displayView.js';
import { renderBoardView } from '../board/boardViewRenderer.js';

/**
 * @param {{ apply: (view: object|null) => void, container: HTMLElement }} options
 * @returns {{
 *   activate(): void,
 *   deactivate(): void,
 *   render(view: object|null): void,
 *   getPresentationMode(): 'dm'|'player',
 *   setPresentationMode(mode: 'dm'|'player'): void,
 * }}
 */
export function createDmScreen({ apply, container }) { }
```

Contract:
- Internal state: `presentationMode`, starting at `'dm'`.
- `activate()`: appends exactly one toggle `<button>` into `container` if not already present (idempotent — calling it twice does not create a second button). Does not itself call `render`. Button text should reflect current mode (e.g. "Preview as player" when in `'dm'` mode, "Return to DM view" when in `'player'` mode) and update on toggle.
- Clicking the toggle button calls the same logic as `setPresentationMode` with the opposite of the current mode.
- `setPresentationMode(mode)`:
  - Setting `'dm'`: hide+clear the preview panel (see below); the next `render(view)` call will go to `apply(view)`.
  - Setting `'player'`: the next `render(view)` call will call `apply(null)` (hiding the DM's own real panel) and render into the preview panel instead.
  - Setting the mode it is already in is a harmless no-op (no flicker, no re-render triggered by the setter itself — only the next `render()` call actually paints anything).
- `render(view)`:
  - `presentationMode === 'dm'`: calls `apply(view)` with the **exact, unmodified** `view` it was given — never call `deriveDisplayView` in this branch.
  - `presentationMode === 'player'`: calls `apply(null)`, then lazily creates (once) a preview panel — `<section id="dmPreviewPanel" class="realtime-session-panel dm-preview-panel">`, appended to `document.body`, hidden by default — and calls `renderBoardView(previewPanel, deriveDisplayView(view, 'player'), { presentationMode: 'player' })`.
- `deactivate()`: hides the toggle button (do not remove it from the DOM — `activate()` must be able to re-show the same button without recreating it), hides+clears the preview panel if it exists, and resets `presentationMode` to `'dm'`.
- `getPresentationMode()`: returns the current mode string — a plain test/inspection hook, not used by production wiring logic itself.
